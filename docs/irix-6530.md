# IRIX 6.5.30 as a second IRIX root

`install-irix6530.sh` installs IRIX 6.5.30 from the IRIX CDs into
`/irix6530`, next to the IRIX 6.5.27m tree that QuickTransit's RPM puts in
`/irix`. `/irix` and everything in it (SGUG, the desktop extras) stays as it
is. The new tree has every product on the CDs, development tools included:
headers and libraries, the MIPSpro 7.4 compilers, `dbx`, WorkShop and
SpeedShop.

    ./install-irix6530.sh <cd> ...       # after install.sh (+ install-extras.sh)
    irix6530 uname -aR                   # IRIX64 <host> 6.5 07141529 IP30 6.5 6.5.30m
    irix6530                             # IRIX shell in the 6.5.30 tree
    irix6530 cc -o hello hello.c         # MIPSpro 7.4
    start4dwm-6530                       # desktop session (needs install-extras.sh)

## Media

Each CD is given once, as a tar archive of the CD or as a directory (its
`dist`, or a directory above it). Base CDs and overlays all go in; for each
subsystem the newest version wins (see "How products are installed").
Tested set:

The Base Documentation CD has no `inst` products and is skipped. Don't give
a directory that merges several CDs' `dist` directories into one: products
with the same name on two CDs (`arraysvcs` on both Applications CDs)
overwrite each other's `.idb` or archive there and no longer match.

With the CDs above, the run takes about 35 minutes on a 1.5 GHz Itanium 2
and the tree is 5.3 GB. CD archives are unpacked to `/var/tmp` first (about
3 GB more for the set above, deleted afterwards).

## How products are installed

`irix-dist-extract.py --install` does what `inst` would with every
subsystem selected, without running IRIX:

- A *full image* of a subsystem is one in a product of the same name
  (`eoe.sw.base` in `eoe.idb`). The newest full image (by `.idb` date)
  replaces older ones: DF 1.3's `compiler_dev` 7.4 replaces the All-Compiler
  CD's 7.3, Applications August 2006's `desktop_eoe` replaces June 1998's.
- An *overlay image* is one in a product with another name (`eoe.sw.base`
  in `eoe_6530m.idb`, `compiler_eoe.sw.lib` in `compiler_eoe_744_6530m.idb`).
  Overlays list only the files that changed, so they go on top of the full
  image, if they are newer than it.
- Images are laid down oldest first, so where two subsystems ship the same
  file the newer one wins.
- `mach()` selects the files for the machine QuickTransit says it is: an
  Octane (`CPUBOARD=IP30`), IRIX64 (`MODE=64bit`), MGRAS graphics
  (`GFXBOARD=MGRAS`, `SUBGR=RACER`), 6.5.30m (`TARGOS=1289662620`).
- Absolute symlinks are made relative (`usr/bsd/mailq -> /usr/lib/sendmail`
  becomes `../lib/sendmail`), as in QuickTransit's own `/irix`.
  QuickTransit maps the paths IRIX programs use into the IRIX root, but
  symlinks are followed by the host kernel, so an absolute target would be
  looked up on the host. Nothing is written through a link that leads out of
  the root.
- Where an older product made a directory that a newer subsystem wants as a
  symlink (`usr/adm -> ../var/adm`), the directory's contents are moved to
  the link's target first.
- `delhist` entries (history bookkeeping, e.g. `var/tmp symval(/XYZ)`) are
  skipped.

Formats met on the media: entries with `off()` (6.5.x images) and without
(older images such as Applications June 1998: entries follow each other in
the archive in `.idb` order); the subsystem after the attributes instead of
in field 7 (`sysadmdesktop_6530m`); flags (`nohist`, `needrqs`, `delhist`,
...) before it; destination paths with `..` (`usr/gfx/ucode/MG/../ge11_*`);
attribute values with parentheses inside quotes (`exitop("(chroot $rbase
...)")`).

The products' install scripts (`exitop`, `postop`, ...) are not run by the
extractor; they are listed at the end of
`/irix6530/var/adm/install-irix6530.log`. Running them all is not safe here:
some edit `/etc/passwd` and the like, which in the IRIX root are links to the
host's files, or start daemons. `install-irix6530.sh` runs the two kinds that
matter and only make files in the tree:

- Motif's `mksymlinks` (from `motif_dev`, `ViewKit_dev`, `motif_eoe`, ...):
  the links that make Motif 1.2 the default, `/usr/include/Xm ->
  ../Motif-1.2/include/Xm`, `/usr/lib32/libXm.so`, ... No `.idb` has them;
  without them `#include <Xm/Xm.h>` fails. Run on the host (`sh`), it only
  makes relative links.
- `make` in `/usr/lib/filetype` (from most desktop products): the desktop's
  file-type database (`desktop.otr`), run under QuickTransit (~2 min).

Not run: online-book indexes (`insightAdmin`), `iconcatalogedit` (the Icon
Catalog pages from the media are there; a few dozen added by install scripts
are not), the Type1 `.pfa` links into `/usr/lib/DPS/outline/base`, mail,
NIS, network and `rc` scripts. Compared with a real 6.5.30 Octane, the only
links missing from `/usr/include`, `/usr/lib*`, `/usr/bin`, `/etc` and
`/var` are those, and of its 3,080 headers, compiler files and libraries
only `/usr/include/sys/fs/autofs_prot.h` (made by `rpcgen` at build time).

## Host glue

As in QuickTransit's `/irix` (from the RPM), these are links to the host:

- `dev/console`, `log`, `null`, `stdin`, `tty`, `zero`, `mmem` (to
  `/dev/zero`), `ttys` (to `/dev/pts`), `ttyd1`/`ttyd2`; `dev/kmem` is an
  empty file
- `etc/passwd`, `group`, `shadow`, `hosts`, `resolv.conf`, `services`,
  `nsswitch.conf`, `aliases`, `ftpusers`, `hosts.equiv`, `inetd.conf`
- `home`, `mnt`, `root`, `tmp`

and these files, which IRIX writes at boot and no CD has, are created as in
`/irix`: `etc/mtab` (fam loops on "couldn't open /etc/mtab" until its stack
overflows without it, and fm then shows "The File Alteration Monitor has
stopped responding"), `etc/fstab`, `var/adm/utmp`.

`QTBindIRIX.sh` (the QuickTransit RPM's `%post`) is then run on the tree: it
links QuickTransit's `libGL`, `libmpi` and `libsma` in place of SGI's,
puts wrapper scripts in place of `su`, `lp`, `at`, ..., and a "not
supported" stub in place of a few programs. `waitmap` is put back, as
`install-extras.sh` does for `/irix`. If `install-extras.sh` was run, its
`fam.conf` and ALSA `libaudio` are installed too.

## Running programs in it

QuickTransit's IRIX root is set by `FU_IRIX_ROOT` in its config file;
`DYNAMITE_CONFIG_FILE` names another config file to read instead of
`QuickTransit.conf`. `install-irix6530.sh` writes
`/usr/QuickTransit/etc/QuickTransit-6530.conf`: a copy of
`QuickTransit.conf` plus

    FU_IRIX_ROOT=/irix6530
    FE_INTERPRETER_FSROOT=/irix6530
    FU_PLATFORM_RELEASEREVNAME=30m         # uname -R: "6.5 6.5.30m"

and `/usr/bin/irix6530` sets `DYNAMITE_CONFIG_FILE` to it.
`FE_INTERPRETER_FSROOT` is needed as well: without it every program gets
`/irix`'s 6.5.27 `libc.so.1` with 6.5.30 libraries (see
[qt-internals.md](qt-internals.md#irix-root)). Child processes
inherit the variable, so everything started from there runs in the 6.5.30
tree. An IRIX binary started without it (by binfmt_misc, from a host shell)
gets the default root `/irix`.

The working directory has to be visible from the IRIX root (under `/home`,
`/root`, `/tmp`, `/mnt` or `/irix6530`); QuickTransit refuses to start
otherwise ("..which is not visible from the irix world").

## Desktop

With `install-extras.sh` run, `start4dwm-6530` is `start4dwm-x11` for this
tree: it sets `IRIX_ROOT=/irix6530` and `DYNAMITE_CONFIG_FILE` for
`irix-desktop`, which then runs the tree's own `Xsession.dt` and fam. fam
resolves the paths it watches in its own tree, so a fam from the other tree
is stopped first. `irix-desktop` learned `IRIX_ROOT` together with
`install-irix6530.sh`, so an older `install-extras.sh` run has to be repeated
first. Tested: 4Dwm, toolchest, fm with icons, background icons, Icon
Catalog, winterm.

## Development tools

| Tool | Status |
|---|---|
| `cc`, `c89`, `c99` (MIPSpro 7.4 C) | work: n32 and 64-bit, `-g`, `-O0` to `-O2`, Motif/X11 programs |
| `CC` (MIPSpro 7.4 C++) | works (`-LANG:std` too) |
| `cc -O3` | no output (without a license) |
| `f77`, `f90` | don't work: the Fortran front ends on these CDs are 7.3 (All-Compiler CD); the 7.4 back end rejects their output, "Invalid format revision (WHIRL::0.31:) for intermediate compiler file". Needs the MIPSpro 7.4 Fortran CDs. |
| `make` (IRIX), `smake`, `pmake` | `make` works (builds the file-type database) |
| headers, libraries | `irix_dev`, `x_dev`, `motif_dev`, `gl_dev`, `dmedia_dev`, `inventor_dev`, `ViewKit_dev`, ... at 6.5.30 |
| `dbx`, WorkShop (`cvd`), SpeedShop | installed, untested |

No license is installed, and the kit does nothing about licensing. Without
one, each MIPSpro command prints the FLEXlm notice (`No such feature exists
(-5,116)`, "The MIPSpro C Compiler (license FEATURE string = cc) requires a
license password ...") and then compiles anyway, exit status 0, except as
noted above. A valid `license.dat` would go in `/irix6530/var/flexlm/`.

The SGUG gcc ([irix-gcc.md](irix-gcc.md)) is in `/irix`, not in this tree.

## Known issues

- `uname -v` still says `07141529` (the 6.5.27 build); a real 6.5.30f says
  `07202013`. No config option for it was found.
- The CDs give the 6.5.30 maintenance stream (`6.5.30m` overlays); `/irix`'s
  Netscape 4.8 isn't on them (Applications June 1998 has an older one).
- An IRIX program started from a host shell without `irix6530` (binfmt_misc)
  runs in `/irix`.
- `/irix6530.old` (the previous tree after a re-run) takes another ~5 GB until
  deleted.
- A re-run moves the old tree to `/irix6530.old` while programs from it may
  still be running. Stop the 6.5.30 desktop session first. On an NFS root,
  files still open stay behind as `.nfs*` and keep `/irix6530.old` from
  being deleted until the process holding them ends; `fuser -m` or `lsof`
  finds it. It can be a QuickTransit process whose main thread has exited
  while other threads live on: its command line is empty, so
  `pkill -f QuickTransit` misses it.
